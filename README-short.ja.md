## 問題

Cardano はトレジャリー・ガバナンスの分散化に成功しました。DRep、憲法上のガードレール、トレジャリー引出、委任投票により、多くのブロックチェーン・エコシステムがまだ到達していない基盤が築かれました。

次の課題は正当性ではなく、**スケールと責任ある管理** です。数千の ADA 保有者、数百の DRep、管理者、監査人、ベンダー、将来の参加者が、運用上の複雑さに溺れながら持続可能に戦略的判断を下すことはできません。

本提案は同時に、憲法が **持続的で安定化する憲法上の要素** — 役割、権利、ガードレール、説明責任 — に集中できるよう解放し、市場や状況に継続的に適応しなければならない執行・運用上の規定から距離を置きます。それらの運用上の選択は年次フレームワークに属します。

現行の提案中心モデルは、次のような反復的な摩擦を生みます。

* **DRep の過負荷** — 有権者に戦略家、調達担当、監査人、プロジェクトマネージャーを同時に求める
* **提案の過負荷** — 無関係なイニシアチブが同時に届き、意味のある比較ができない
* **比較可能性の弱さ** — 類似の仕事が異なる構造・条件・前提で提示される
* **構造化された共同資金シグナルの欠如** — ほぼすべての申請が全額トレジャリー資金を求め、トレジャリー比率のランク付け可能なメタデータがない
* **予算フェーズの曖昧さ** — Net Change Limit ラウンドは固定の引き継ぎなしに互いに置き換わり得るため、複数四半期の計画と説明責任が不明確
* **実行のギャップ** — 次ラウンド前の部分返金や自発的返還は成果提供の代わりになってはならない。実績は次の予算年度に引き継がれるべき
* **NCL 予算ロック** — 大規模承認予算が未達でも NCL 容量を消費し、再配分できない。未達成果がサイクル後半まで不明なまま、他の提案者が拒否される

相当規模の承認予算を持つ提案者は、プロジェクト量の相当部分について完全に成果を出せず、またはマイルストーン承認を得られないことが多い — それでも当該金額は NCL から既に差し引かれ、他プロジェクトに回せなかった。これは約束した成果の欠落にとどまらず、NCL 上限に入れなかった他の参加者への経済的損害でもある。

多くの大規模組織は、戦略計画、予算配分、調達、管理、監査、実行を分離しています。Cardano ガバナンスは現状、その負荷の多くを直接有権者に置いています。これはスケールしません。

## コンセプト

本提案は、トレジャリー・ガバナンスを **提案中心** モデルから **戦略的予算** モデルへ進化させます。

### フレームワークとカテゴリの意味

**フレームワーク** は1予算年度分の完全な戦略ブループリントです。年間トレジャリー枠の分割方法、どの **カテゴリ** が存在するか、各レーンに適用されるルールを定義します。**カテゴリ** はテーマ別の資金領域 — スコープ、KPI、部分予算の割合 — であり、個別プロジェクトではありません。ベンダーは DRep がフレームワークを採択した **後に**、カテゴリ **内** でプロジェクト枠を競います。

説明例 — 同一予算年度向けの2つの競合 Q4 提案（架空の数値。年間枠 50M ADA と仮定）:

| カテゴリ | フレームワーク A —「Builder-first」 | フレームワーク B —「Enterprise & security」 |
| -------- | ----------------------------------- | ------------------------------------------ |
| Core infrastructure & reliability | 18M ADA (36%) | 14M ADA (28%) |
| Developer tooling & SDKs | 12M ADA (24%) | — |
| Education & onboarding | 8M ADA (16%) | 4M ADA (8%) |
| Governance tooling & DRep support | 7M ADA (14%) | — |
| Open innovation (広いスコープ) | 5M ADA (10%) | — |
| Enterprise & real-world integrations | — | 15M ADA (30%) |
| Community & events | — | 9M ADA (18%) |
| Security audits & formal methods | — | 8M ADA (16%) |
| **合計** | **50M ADA (100%)** | **50M ADA (100%)** |

DRep は **フレームワーク全体** の選好を順位付けします — カテゴリを個別には選びません。勝ったフレームワークが、その年のカテゴリ構成と部分予算割合を確定します。例: フレームワーク A では、チームが Q1 に「Developer tooling & SDKs」内でウォレット SDK プロジェクトを競う。フレームワーク B ではそのカテゴリは存在しないが、「Security audits & formal methods」がウォレットライブラリの監査を資金調達する場合がある。

概要:

1. **年次フレームワークを先に** — Q4 に競合フレームワークがカテゴリ、予算、KPI、運用ルールを翌予算年度分定義。DRep は無関係な数百提案を一度に扱うのではなく、選好投票で選択。
2. **カテゴリ内の四半期競争** — ベンダーは有効フレームワークが定めた共通スコープ、レーン、KPI 内で競う。
3. **比較可能な提出物** — 人間可読の叙述と機械可読フィールドを備えた構造化テンプレート。
4. **トレジャリー比率と共同資金を事前に** — 各引出申請が、トレジャリーと提案者負担の割合を宣言。
5. **強力な開示** — 利益相反と第三者関係を投票前に宣言。
6. **Option 0 を常に票に** — トレジャリー留保がすべての資金決定と競合。支出は正当化が必要。
7. **役割の分離** — DRep が方向と信頼を決定。ベンダー、管理者、監査人は憲法上のガードレール下で競争。

本フレームワークは公共調達と企業予算の有効なパターンを借りつつ、**中央権限のない分散ガバナンス** として配置します。ルールが競技場を定義し、DRep は各段階で選択権を保持。年次フレームワーク、カテゴリ、調達構造は中央計画ではありません。

![コンセプト概要](docs/diagrams/moreViableGovernance_sticks-usecases.png)

*これはガバナンスの実験から成熟への道を創ります。*

## 予算年度の進め方

予算年度は **暦に沿い固定** — いつでも置き換わり得る NCL ラウンドとは対照的です。

| 時期 | 内容 | 決定者 |
| ---- | ---- | ------ |
| **Q4** | フレームワーク提案の提出。DRep が翌年度の年次フレームワークを順位付け投票 | DRep |
| **Q4** | 当年度の観察可能な実績を踏まえた管理者信頼の再配分 | DRep |
| **各四半期** | カテゴリ内プロジェクト提出 → チャレンジ期間 → 精緻化 → 確認投票 | DRep。確認時に監査人 |
| **通年** | マイルストーン提供、報告、検証。評判は引き継がれる | 管理者、監査人 |

![年次ガバナンス・サイクル](docs/diagrams/generated/annual-cycle.svg)

**フレームワーク選定。** Q4 に誰でも完全なガバナンス・フレームワークを提出可能。作成者は標準テンプレートで身元、利害、利益相反を開示。DRep が順序付き選好を表明し、最も強い集合的選好が翌予算年度で有効に。カテゴリは恒久ではない — 毎年、憲法ガードレール内でまったく新しい戦略構造を選べる。

**カテゴリ競争。** フレームワーク承認後、カテゴリは四半期ごとに独立運用。四半期投票は優先順位を決め、プロジェクト期間（最大12か月）ではない。複数年フラグは長期意図を可視化するが、将来資金への **権利は生まない** — 各フェーズは独自サイクルで再競争。

**精緻化と確認。** 第一投票で優先提案を特定。その後チャレンジ、明確化、統合、精緻化。予算、共同資金条件、成果物を改善可能。第二確認投票が、担当監査人と最終資金条件とともに精緻化提案を批准。

**データとしてのガバナンス。** 提案、フレームワーク、開示、投票に構造化フィールドを用い、DRep とツールが大規模にフィルタ、比較、事前評価可能に。

*これは予測可能性を創ります。誰もが決定のタイミングを知ります。*

選好投票方式、トレジャリー比率フィールド、チャレンジの仕組み、資金スロット、新参レーンの詳細: [README — Part III](README.md#part-iii---annual-budget-model) _(English)_.

## 設計原則

| 原則 | 意味 | これが創るもの |
| ---- | ---- | -------------- |
| **運用より戦略** | DRep は優先順位、予算、信頼、プロジェクト選定を決定 — 日々の PM ではない。実行ルールは個別提案添付ではなく共通フレームワークに属する | 明確さ — 戦略的判断は有権者、実行は競争に開放 |
| **固定年次カレンダー** | 既知の Q4 フレームワーク・信頼投票。四半期カテゴリ競争。明示的予算年度境界 | 予測可能性 — 計画と資金付き作業への説明責任 |
| **Option 0** | 各競争に「不交付／トレジャリー留保」を支出オプションと並置 | トレジャリー保護 — 支出の正当化が必要 |
| **共同資金メタデータ** | トレジャリー比率は各申請の構造化・フィルタ可能フィールド。100% トレジャリー資金も有効 | 比較可能性 — 投票前に提案者コミットメントが可視 |
| **制度記憶** | 提供履歴は次予算年度へ。部分返金は低パフォーマンスを消さない | 説明責任 — 時間を通じた実績の可視化 |
| **至る所で競争** | フレームワーク、ベンダー、管理者、監査人がすべて競争。代替不能な役割なし | 回復力 — 単一主体が不可欠にならない |

**憲法層と運用層。** 憲法は役割、責任、制約、タイムライン、トレジャリー・ガードレール、説明責任メカニズムを定義。年次フレームワークは1予算年度の運用実行モデル（カテゴリ、予算、KPI、プロセス）を定義。戦略は憲法修正なしに進化可能。

![分散された役割と権力](docs/diagrams/generated/role-model_proposer-dreps.svg)

*これは柔軟性を創ります。憲法上の安定性を保ちながら戦略が進化。*

**範囲。** 本提案は **トレジャリーと予算ガバナンスのみ** を扱う。憲法修正、パラメータ変更、ハードフォーク、情報アクションは既存プロセスを継続。

## 役割

| 役割 | 提案内容 | DRep が決定 | 競争軸 |
| ---- | -------- | ----------- | ------ |
| **フレームワーク作成者** | 完全な年次戦略ブループリント（カテゴリ、予算、KPI、管理／監査モデル） | Q4 選好投票 | 実績、透明性、開示 |
| **ベンダー** | 定義スコープ・レーン内のカテゴリプロジェクト | 四半期選好投票 | 提供品質と価値 |
| **管理者** | 運用信頼の入札 | Q4 信頼配分 | 報告品質、容量、信頼性 |
| **監査人** | 検証サービス | プロジェクトごとの確認 | 専門性、独立性、価格 |

権力は分散: フレームワーク設計者は唯一のプロセスを定義しない。管理者は提案手数料ではなく信頼で競争。監査人は競争市場に登録。いかなる役割も自己定義で回避不能であってはならない。

*これはバランスを創ります。永久で異議申立不能なガバナンス主体なしに、戦略的方向を民主的に選択。*

ベンダー身元の段階、評判の仕組み、容量制限、監査人ローテーション: [README — Part IV](README.md#part-iv---roles-and-accountability) _(English)_.

## 参加者別の便益

| 参加者 | 主な利点 |
| ------ | -------- |
| **ADA 保有者** | より明確な優先順位、予測可能な支出サイクル、透明な実績履歴、DRep が戦略に集中する際の委任の容易さ |
| **DRep** | ガバナンスフェーズごとに一つの問い。構造化された比較可能提案。機械可読フィルタ。方向、予算、信頼に集中 |
| **ベンダー** | 既知のカテゴリスコープと KPI。レーン内の公正競争。新参から大規模プロジェクトへの道。Option 0 が価値正当化を強制 |
| **管理者** | 提案者手数料ではなく DRep 信頼からの委任。運用卓越性の競争市場 |
| **監査人** | 定義された役割、登録専門性、カテゴリ横断の競争機会 |
| **フレームワーク作成者** | 年次方向を形作る可視的役割。断片的議論ではなく完全戦略間の競争 |

*これは整合を創ります。全参加者がより明確なルール、より公正な競争、より少ない曖昧な責任を得ます。*

## 主要リスク（要約）

| リスク | 対策 |
| ------ | ---- |
| フレームワーク掌握 | オープン Q4 提出、DRep 順位投票、義務開示、年次リセット |
| 自己定義的独占役割 | 代替不能な管理者・監査人なし。提案側すべてが競争 |
| 弱い提供説明責任 | マイルストーン、監査人検証、予算年度横断の評判。返金のみでのリセット不可 |
| 曖昧な予算フェーズ（NCL） | 固定年次サイクル、既知の Q4・四半期カレンダー |
| 官僚制の印象 | ガバナンス最小化 — より少なく、より高価値な DRep 決定 |

最強の保護は建築的: DRep がそもそもどの決定を下すべきかを問うことで、投票 mechanics 最適化だけでなく攻撃面を縮小。Cardano のトレジャリー課題は主に **ガバナンス・アーキテクチャ** の問題であり、投票の問題ではない。

*これは回復力を創ります。既知リスクに善意の仮定ではなく名指しの対策。*

完全なリスク表と対策: [README — Risks and Safeguards](README.md#risks-and-safeguards) _(English)_.

## ステータスと次のステップ

これは **生のコンセプト草案** — 経験豊富な DRep がトレジャリー・ガバナンスの根本的見直しを支持するか試すには十分具体だが、運用詳細は意図的に未完成。

**協調的起草が主目的。** 本文は議論を開く。完成した改革ではない。方向性に支持が得られれば、次段階でより多くの DRep をワークショップ、レビュー、微調整に招くべき。

初期導入は段階的に可能 — 年次フレームワーク提案、カテゴリ定義、選好ベース選定、構造化チャレンジ — 既存メカニズムを維持しつつ。パイロット設計、段階的モジュール、法務レビュー時期: [Path Forward](docs/path-forward.md) _(English)_.

*これは実用的な前進の道を創ります。混乱なく進化が可能に。*
